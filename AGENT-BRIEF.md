## Owner's hard rules for geometry
1. No special cases. A few general operations apply to every input alike. No code that recognises
   a hairpin, V, T, cusp, junction type or class pair and builds a dedicated shape. No repair pass
   that patches output. A wrong-looking case changes a general operation or a rule value, proven
   over the whole fixture. List every case distinction that remains, with its reason.
2. Thin parts of correct geometry are valid. Only artefacts are faults: shards across a way,
   numerical slivers, 1-unit jogs, stranded fragments, overlaps, gaps. Tapers, land narrowing to a
   point, a round running tangentially into an edge are wanted.
3. The inner edge of every inward corner has a radius of at least the class `inner_radius_m`;
   junction corners use the pair radius; road/path is 1 m.
4. GP3's approach: strokes with round joins, a tangent arc at each inward corner, priority labels,
   one integer overlay per cell; no closings.

## This machine (NOT timosPC)
- 4 cores, 15 GB RAM, no swap, 30 GB free disk. NO GPU (no /dev/dri). No /media/timo/OSM1.
- Memory and time cap for every heavy run (benches, fixture runs, debug tool, shoots, vitest of
  the whole trailview folder): `capped -m 3G -t 600 <cmd>` (cgroup v1 cap + timeout; it is in
  ~/.local/bin). It is the equivalent of timosPC's systemd-run line.
- At most 4 threads for benches. `export CARGO_BUILD_JOBS=4`.
- `obc` is ~/.local/bin/obc (needs `just`, installed). Run commands through `obc` / `obc exec`.
- Pictures: `/home/user/gp-pictures/gp<k>/` with an INDEX.md (one line per picture: what it
  shows, does it look right). Look at every picture yourself (Read tool) before you claim a result.
- Viewer shots: there is no GPU, so `shoot.mjs` WITHOUT `--gpu` (SwiftShader, slow; use
  `--pages 1` or 2, and few views per run). Still hold the lock: `flock /tmp/trailview-gpu.lock`.
  GPU timings (flight.mjs, ms per stamp job) on SwiftShader are NOT the GTX numbers: report them
  only as a relative old/new comparison on SwiftShader, labelled as such; the owner re-measures on
  the GTX box.
- Shared cargo target: never run a prebuilt binary from it; use
  `obc exec cargo run --release -p <crate> --example <tool> -- ...`.
- Work in your own git worktree (`git worktree add /home/user/wt/<name> <branch>`), not in
  /home/user/OpenBikeComputer (the orchestrator's checkout).
