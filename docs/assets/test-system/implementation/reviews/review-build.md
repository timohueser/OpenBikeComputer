# review:build — Build-time and Cargo feasibility of §2.7 (build levers) and §2.5 (selection/CI), verified against manifests, test sources, ci.yml and the build-time survey; no builds run.

## verdict
The consolidation lever (§2.7 row 1) is real and nearly blocker-free: 23 crates' tests/ dirs merge into one target each except obcm-assemble (a #[global_allocator] test) and obc-wx-bake (CI partitions heavy suites by binary), landing at ~75 executables as claimed. The plan's two Cargo-level premises are not sound as written: (1) "one feature shape = per-package defaults" cannot coexist with "one nextest invocation" because resolver 2 unifies features across every package in the invocation, so the obc-formats default-shape step does not disappear and local/CI artifacts do not converge; (2) a nextest filterset filters what runs, not what compiles, so `nextest run -E '<affected + rdeps>'` alone leaves CI's compile (the bulk of the 93 s step) at the full workspace. Both are fixable by wording and by emitting `-p` flags, but the plan's §2.7 row 3 payoffs and §1.3 "one function" rationale for the obc-route dev-dep cut are overstated.

- **[§2.5 Rust job: `cargo nextest run -E '<affected packages + rdeps>'`]** A nextest filterset selects which tests RUN; the set of test binaries COMPILED is whatever the cargo arguments select (`--workspace` by default in a virtual workspace with no default-members). Without `-p` flags, CI still compiles every test target on every run, and the 93 s nextest step is mostly compile (survey: ~40 s of it is test execution).
  evidence: `cargo nextest help filterset` on the installed 0.9.143 confirms package()/rdeps() exist ('Include all tests in crates matching name-matcher, and all the crates that (possibly transitively) depend on name-matcher') but describes test inclusion only; nextest forwards cargo build args and evaluates -E after `cargo test --no-run`. Cargo.toml has no default-members (grep). ci.yml:284 today: `--workspace --all-features ... -E 'not package(obc-wx-bake)'` — the exclusion does not skip compiling obc-wx-bake. survey-build-time.md line 30: rust-cache strips workspace crates, so every CI run recompiles the 41 members + 159 binaries; nextest step 93 s = compile + ~40 s run (confirmed by run 34727869462: 00:25:10 → 00:26:43).
  change: Make the selection emit `cargo nextest run -p <a> -p <b> ...` from the existing reverse-dependency closure (tools/suite_registry.py:637-669 builds reverse edges from cargo metadata; 941-950 walks them); use -E only to carve heavy tests out. State explicitly that the compile saving comes from `-p`, not from the filterset. On rdeps() and dev-dependency edges: nextest builds its package graph with guppy over cargo metadata, whose resolve includes dev-dependency edges of workspace members, and rdeps follows all link kinds — I am ~85% confident dev-dep edges are included, but the plan should not depend on it because the Python closure already computes the same set from `dependencies` (kind included).

- **[§2.5 / §2.7 rows 4-5: job restructuring vs the rust-cache]** Three cache facts the restructuring must respect are not in the plan: the develop-push run writes the only cache and must stay a full build; workspace members are never cached, so every split-out job pays a members compile that is free today; restore-only consumers must build the same shape as the writer.
  evidence: ci.yml:258-262: `shared-key: host-tests`, `save-if: ${{ github.event_name == 'push' }}`; ci.yml:409-412 the weather legs restore that key with save-if false. rust-cache caches are immutable per key (Cargo.lock hash + rustc), and ci.yml sets no `cache-workspace-crates` (grep), so member artifacts are rebuilt every run (survey line 30). Today the sweep reuses the nextest-built obc-sim (ci.yml:318-321 comment: 'the tests above have already built it') and obc-bench --check is 6 s (run 34727869462: 00:26:49 → 00:26:55); pytest's `cargo build -p obc-pack --release` is 28 s incl. pip (ci.yml:336-340). Each new job also pays rust-cache restore (13 s) and setup-host-deps (16 s) per the same run.
  change: Add to §2.5: (a) the push-to-develop Rust job builds the FULL package set (or the cache is saved only by a full run), otherwise a selective push writes a partial cache that persists until the next Cargo.lock change; (b) budget the split-out sweep/bench/pytest jobs at 'cache restore 13 s + host-deps 16 s + cold members compile (obc-sim debug, obc-bench and obc-pack release)' each — wall improves by parallelism, runner-minutes rise, and the '~80 runner-s' saved by the policy-job merge is likely consumed; (c) any restore-only job must use the writer's feature shape and `-p` set or it recompiles missing deps on every PR.

- For the GEOS-free writer split: is moving ~5.8k LOC (nav, serialize, poi, hours, grid) out of obc-pack acceptable in the 'speed first' PR, or should obc-route's tests instead stop using the packer's writer (obcm-testkit already hand-writes OBCM bytes) so the dev-dep can simply be deleted?
