# review:loc — LOC honesty and deletion safety

## verdict
The deletion list is mostly real: about 10–11k lines of it survive a per-row check, and the S0/ledger/nowcast/bins rows are safe as stated. But the plan's size numbers are not on one convention (inline LOC counts firmware only, python tests are 302 not 150, tooling tests are 3,992 not 2,700, so the base is ~165k not ~140k), three rows are mis-scoped (bench_ingest has no death trigger and is still the documented map-loading path for the CI bench binary; dirty.rs has ~8 no-repaint assertions dirty_parity cannot imply, not two; 'legacy pins' is ~190 lines, not 350), and the −12k net is the optimistic edge of a −6k…−11.5k range because the '−6k consolidation' double-counts the sweep and loopback.ts and the additions omit the 317-frame Rust scenario table, the job scripts, the stdio process and the vectors producer. The biggest single issue: §0 says '~10k', §2.8 says '−12k', and neither states the counting convention that would make either checkable.
