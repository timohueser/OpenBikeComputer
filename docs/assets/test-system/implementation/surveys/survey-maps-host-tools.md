# maps-host-tools — Map pipeline, rendering, navigation and host tools: host/obc-pack, obc-bake, obc-dem, obcm-assemble, apps/obc-web-assemble, firmware/obc-reader, obc-render, obc-route, obc-elevation, obc-map-scene, host/obc-bench, obcm-testkit, obc-fixtures, the fixture registry (fixtures/, tools/fixtures.py), obc-mkimage, obc-usb, obc-usb-host, obc-tree-walk (read-only survey at develop d42e2e3a, 2026-09-13)

## how_it_works
Mechanism, from the ground up.

1. What drives the code. Every crate in this area is host-runnable; nothing needs hardware. The map pipeline is driven three ways: (a) hand-written spec-mirroring bytes from host/obcm-testkit (lib.rs:1-56 explains why: a fixture built by the production writer only proves self-consistency), used by obc-reader/tests/format.rs, obc-render/tests/priority.rs, obc-app POI tests, obc-storage map_read.rs:24, obc-host-core dispatch.rs:976, obc-sim map_file.rs:148; (b) the real writer obc_pack::serialize_lods used as the fixture writer by obc-pack/tests/round_trip.rs:17, nav_round_trip.rs:31, obc-route/tests/nav.rs:12-13 and detour.rs, obcm-assemble/tests/oracle.rs:30-39; (c) real captured data: builder/tests/corpus/data/*.osm.pbf (sub-KB, hand-authored OSM) for ingest/cut/pipeline/bake tests, and the content-addressed R2 packages (fixtures/catalog.toml) for grimsel/monaco, resolved through host/obc-fixtures/src/lib.rs:32-51.

2. Seams and fakes. obc_formats::io::{ByteSource, ByteSink} is the I/O seam: tests implement SliceSource (production), read-counting sources (obc-reader/tests/common/mod.rs:21-49 and 7 more copies) and Vec-backed sinks (17 copies, see duplication). obc_map_scene::MapScene (firmware/obc-map-scene/src/lib.rs:1-9) lets obc-render/tests/static_scene.rs:20-31 render without OBCM bytes. embedded_graphics::DrawTarget is the pixel seam: obc-render/tests/common/mod.rs:14-84 (Buf, Rgb888) and :88-139 (BitBuf), obc-app/src/harness/support.rs:33 (Buf, included by path into tests via obc-app/tests/common/mod.rs:8), obc_display::Framebuffer565 (the real device buffer) in obcm-assemble oracle.rs:28 and obc-bench. obc_elevation::{ElevationSource, NullElevation} is the terrain seam (NullElevation in every pack test). Scratch directories: obcm_testkit::scratch (scratch.rs:24-38) plus three hand-rolled copies.

3. What the assertions are on. Byte pins (obc-pack/tests/serialize.rs, obc-reader format.rs, obc-route format.rs over common::build_obcr at common/mod.rs:155-276, obc-elevation format.rs:50), decoded-topology equality after a writer->reader loop (round_trip.rs, nav_round_trip.rs, cell_cut.rs), pixel counts/colours in recording buffers (render tests, arrows.rs), whole-frame equality between two real pipelines (oracle.rs:596-719: pack vs cut+assemble must render and route identically), frame hashes + I/O read counters against a committed file (obc-bench golden.txt, main.rs:750-790), SHA-256 of headless simulator PNGs (ui-snapshots.sha256, checked by firmware/tools/ui_snapshot_manifest.py), checked-in expected .obcm bytes (obc-web-assemble determinism.rs), and CLI process exit/stdout/output files for obc-bake, obc-mkimage and obc-pack pipeline.rs (CARGO_BIN_EXE).

4. How they are selected and run. testing/suites.toml maps one suite per Cargo package with `command = cargo test -p X --locked`. Locally, `obc test affected` runs those commands verbatim via tools/suite_registry.py run_plan (:1192-1222) with no fixture sync, no OBC_REQUIRE_FIXTURES and no `--features external-fixtures`; `obc test -p X` is the same bare cargo test (tools/justfile:606-611); only `obc test full` and `obc test fixtures -p X` sync fixtures and enable the feature (justfile:571-603). In CI the `test` job is gated at job level (ci.yml:241-243) and then runs `cargo nextest run --workspace --all-features -E 'not package(obc-wx-bake)'` (ci.yml:280), followed unconditionally by `cargo run -p obc-bench --release -- --check` (ci.yml:313) and `cargo build -p obc-sim` + the 300-render snapshot sweep (ci.yml:321-325). So the registry's per-suite granularity narrows only local runs; CI always compiles and runs the whole workspace once any Rust suite is affected, and the two golden gates run on every such push.

5. External fixtures. Two gates stacked: a per-crate Cargo feature `external-fixtures` (firmware/obc-reader/Cargo.toml:14, obc-route:13, host/obc-dem:25, obc-host-core:9, obc-wx-bake:9, obc-sim:10) that compiles the tests out, and a runtime Option/panic in obc_fixtures::file (:42-50). Every caller `.expect()`s, so only the feature gate is live. The registry's `fixtures = [...]` names ("test", "captured-dem", "checked-in-assembly", ...) are free strings; suite_registry.py never validates them against catalog.toml (only lines 1052 and 1297 mention the catalog, as a trigger path).

## strengths
- Independent oracles are a deliberate, documented discipline: obcm-testkit (host/obcm-testkit/src/lib.rs:1-10), obc-route common::build_obcr (firmware/obc-route/tests/common/mod.rs:69-77), obc-dem SyntheticDem (host/obc-dem/tests/common/mod.rs:1-9) and obc-dem bake.rs rule 1/2 (:1-11) all refuse to test a writer with its own reader.
- The assembler differential oracle (host/obcm-assemble/tests/oracle.rs) is a genuine multi-crate system test: real cutter, real assembler, real packer, real reader, real renderer into the device framebuffer, real A* — asserting at rider-visible level (pixels and routes). This is the model the owner wants more of.
- Writer->reader loops exist for every format: OBCM geometry (obc-pack/tests/round_trip.rs), nav §8 (nav_round_trip.rs), cells (cell_cut.rs), OBCR (obc-route convert.rs/format.rs), OBCT (obc-dem bake.rs through obc_elevation::TerrainReader).
- Real-process tests where the process is the contract: obc-pack/tests/pipeline.rs (CLI vs library byte identity via CARGO_BIN_EXE), obc-bake/tests/cli.rs (bake.yml's caller), obc-mkimage/tests/cli.rs.
- Content-addressed fixture registry is small, atomic, verified and cached in CI (fixtures/catalog.toml 92 lines; ci.yml:271-275 cache keyed on the catalog hash); provenance is executable (fixtures/build-map-package.sh, apps/obc-web-assemble/tests/fixture.rs).
- Expensive or networked work is already #[ignore]d with a stated reason (obc-dem real_tile.rs:58, decode.rs:35; obc-render rain.rs:1468; web-assemble fixture.rs:330) rather than gated by sleeps or retries.
- The golden gates catch what unit tests cannot: obc-bench pins SD-read counters, not just pixels (golden.txt rows overview/overview-cold), so a cache regression fails on identical frames.
- tools/check_fixture_policy.py (63 LOC) keeps large blobs out of git with an explicit allow-list; the only committed map >256 KB is the product-embedded teningen preview.

## problems
- [high] The registry's per-suite commands are not what CI runs, and the fixture-backed tests only run in CI. CI's test job runs the whole workspace with --all-features once any Rust suite is selected; locally, `obc test affected`/`obc test -p` run `cargo test -p X --locked` without `--features external-fixtures`, so the 5 grimsel route tests, the Monaco reader test, the grimsel terrain test and the whole obc-host-core altitude_fusion file are compiled out. A developer cannot reproduce the CI result for obc-route with the command the registry names for it.

## no_hil_story
Nothing in this area needs hardware or a phone today: the packer, bakery, assembler, DEM baker, reader, renderer, router and elevation sampler are all pure Rust driven on the host, and the device boundaries are already traits with host implementations. The seams, named precisely: `obc_formats::io::ByteSource` / `ByteSink` (firmware/obc-formats/src/io.rs; SliceSource is the production host impl, WindowSource at :114), `obc_map_scene::MapScene` (firmware/obc-map-scene/src/lib.rs:1-9; obc-render/tests/static_scene.rs:20 implements it over static slices), `embedded_graphics::DrawTarget` (obc_display::Framebuffer565 is the real device buffer and is used on the host by obc-bench and obcm-assemble oracle.rs:28), `obc_elevation::ElevationSource` (NullElevation in every pack test), `obc_render::RouteOverlaySource` (obc-render/tests/arrows.rs), `obc_storage::flat::source::StoreSource<D: BlockDevice>` (firmware/obc-storage/src/flat/source.rs:97) and `obc_host_core::flat_store` which already backs a card with a tempfile (host/obc-host-core/src/flat_store.rs:51,216), `obc_platform::DisplayDriver` (obc-sim's present.rs conformance tests await it on the host).

What cannot be exercised without hardware: the SD block layer beneath BlockDevice (embedded-sdmmc timing, CMD18/CMD25 behaviour), the LS021 FLPR partial-update path, the real USB transport under obc-usb (nusb; the obc-usb tests are pure parsers of descriptors and identities), and the wall-clock frame budget on the nRF54L. None of those are map-pipeline correctness questions; they are measured by the bench binaries and resource_guard, which is the right place.

The one seam this area is missing for a host-side system test is the join between the host writer and the device reader over a card image: obc-pack/obcm-assemble output -> flat-store admission (obc-host-core flat_store, tempfile-backed) -> `StoreSource` over that same file -> `obc_app::App` boot -> one rendered frame hash. Every link exists (oracle.rs proves pack->assemble->render; obc-storage/src/flat/map_read.rs:24 proves StoreSource over a testkit map; obc-app tests prove App over testkit maps; ui-snapshots proves sim over grimsel), but no test walks them in one process from a real PBF. The minimal seam is nothing new in production code: a host test crate that depends on obc-pack (or the proposed GEOS-free writer), obcm-assemble, obc-host-core, obc-storage and obc-app, and uses the tempfile-backed flat store as the "card". Adding HIL later means swapping `StoreSource<D>`'s BlockDevice for the real card and re-running the same scenario; adding the phone means driving obc-host-core's dispatch the way the iOS OBCKit does, against the same card image.
