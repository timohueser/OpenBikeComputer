# contracts — Format/protocol/storage contracts and cross-language vectors: obc-formats, obc-crc, obc-link, obc-storage, obc-ble, obc-dfu, obc-boot, host/obc-vectors, specs/vectors/**, specs/*.md, the Swift/TS vector consumers, and the Python guard scripts.

## how_it_works
Three vector pipelines coexist, each with its own producer, pin and consumer shape.

(A) S0/BLE + OBCG/OBCW/OBCT/OBCU/ride/route family (60 top-level files). Producer: Rust builders in host/obc-vectors/src (lib.rs:658 `all()` returns (name, bytes); obcg.rs/obcw.rs go through obc_formats::obcg::encode_format / obcw; route through the real GPX->OBCR converter, lib.rs:83; update-container-v2 signed by obc_dfu::sign_image, lib.rs:396). Pin: `fixtures_match_the_spec_builders` (tests/vectors.rs:285-291) reads every file and compares bytes; regeneration is an #[ignore]d test `regenerate` (:846-853) that rewrites specs/vectors/. Consumers: obc-ble tests/vectors.rs decodes and re-encodes through the production codecs (loader :10-15 uses obc_vectors::dir()); obc-dfu tests/vectors.rs:18 resolves the path from CARGO_MANIFEST_DIR; obc-formats and obc-app include_bytes! specific files (ride.rs:198, obcr.rs:43, weather.rs:749). Expected decoded values live in specs/vectors/manifest.json (1,632 lines), which nothing generates and nothing in Rust verifies (README.md:203-207 tells the human to update it by hand); Swift (OBCGridCodecTests.swift:18,32) and TS (device/route.test.ts:30) read those manifest values as ground truth. Each Swift/TS file also carries its own repo-root walker (9 Swift files with six `.deletingLastPathComponent()`; 8 TS files with `function repoRoot()`).

(B) flat-store-v4 (68 JSON fixtures + manifest with sha256 rows). Producer lives inside the firmware codec crate: firmware/obc-link/src/flat/vectors.rs (1,140 LOC, cfg(any(test, feature="std")), flat/mod.rs:26-27) with a hand-rolled JSON writer (:86-156). Pin: `checked_in_fixtures_match_the_producer` (vectors/tests.rs:36-55) plus codec round-trips of every request/response/error/negative (:76-190) and a transcription of the spec's own §3.11 hex fences (:198-247). Regeneration: #[ignore]d `flat_regenerate` (:19-24). Consumers: Swift FlatStoreVectorTests.swift walks the manifest sections and decodes the `frame`/`bytes` hex (:80-140); TS usb/vectors.test.ts walks the manifest, tracks an `exercised` set, and additionally pins MANIFEST_SHA256 (:84); obc-storage src/flat/vectors.rs independently transcribes FLAT_Store_Format hex fences and the Protocol §3.10 frames.

(C) wx-manifest-v2.json is a hand-authored document; Rust parses it back through the baker's deny_unknown_fields writer model (host/obc-wx-bake/src/manifest_v2.rs:785-800) and obc-wx-client tests; equivalence tables (bbox/rejection/resample) sit in manifest.json and are applied by hand-rolled JSON-patch walkers on each side (README.md 'rejection_equivalence').

Storage and protocol are exercised without hardware through one seam: `BlockDevice` (firmware/obc-storage/src/flat/device.rs, 28 lines). `SparseDisk`/`FaultOnce` (flat/sim.rs) implement it as a deterministic, page-tearing, cut-able card; `model.rs` is the byte-exact reference oracle. crash.rs runs every durable path with a cut at every media op (Before/During/Inside/After, cut census pinned per scenario, :329-1627) and requires the remount to equal the model before or after. obc-link's tests bind the real FlatStore to the transport-free `Engine`/`Link`/`Channel` (tests/flat_harness/mod.rs:109-138) and drive it with hand-built request bytes; flat_break_matrix.rs cuts between link records. The board binds exactly these seams (obc-fw-nrf54l uses obc_storage::flat::{...} and obc_link::flat::{Engine, Link, Channel, Reaction}; Cargo.toml:163-165), so the host harness is structurally the device minus the radio and the SD driver.

DFU: obc-dfu's engine/armer are driven through `InstallIo`/`StageIo`/`ArmIo` mocks that log every operation (tests/engine.rs:40-120, armer.rs:20-50,190-206); obc-boot implements those traits against sEMMC/RRAMC and has no tests (bare-metal binary; CI = clippy + release build + size gate, ci.yml:639-664).

CI execution: the registry routes every Rust suite to the one `test` job, which runs `cargo nextest run --workspace --all-features` (ci.yml:284; routing at tools/suite_registry.py:868-904). rust.obc-vectors is `pull_request = "always"` (suites.toml:370), so `test` (and `clippy`) are required on every PR — verified with `suite_registry.py select --base ffcf1652~1 --head ffcf1652` on a docs+spec-only commit: required_jobs = [..., clippy, ..., test]. Per-crate selection exists only locally (`obc test -p`, tools/justfile:554-600).

## strengths
- The BlockDevice seam (obc-storage/src/flat/device.rs, 28 lines) plus SparseDisk/FaultOnce/When (flat/sim.rs) is a genuine, reusable fault-injection boundary; crash.rs and flat_break_matrix.rs prove atomicity as byte-image claims, not mock agreement (crash.rs:1-27, flat_break_matrix.rs:1-27).
- obc-link/tests/flat_engine.rs (50 tests) runs the production protocol engine against the production store over a torn-able card with hand-built phone bytes — the strongest phone-less system suite in the repo and the right template for more.
- The flat-store-v4 pipeline is the best of the three: one producer, manifest with per-file sha256, manifest-driven runners in Swift and TS, and every spec hex fence verified verbatim (vectors/tests.rs:198-247).
- obc-dfu's install engine is pinned on operation ORDER over a logging mock (engine.rs:40-120), which is the property that bricks a device if wrong; boot-state and OBCU signature have explicit accept/reject matrices (signature.rs, boot_state.rs).
- Fixture producers self-source live constants (obcm::VERSION in version-read.bin, lib.rs:712-716; miniz_oxide pinned =0.8.9 in both obc-formats and obc-vectors) so a format bump cannot leave the vectors silently stale.
- Focused builds are cheap where dev-deps are disciplined: obc-formats and obc-dfu compile 3 crates for their tests.
- check_dependencies.py + dependency_rules.json is a real, tested architectural invariant over cargo metadata (foundation -> core -> app -> platform ordering).

## no_hil_story
Cannot be exercised off-device today: the nRF54L BLE radio and GATT server (firmware/obc-fw-nrf54l/src/ble/*), the sEMMC/SD block driver (obc-boot/src/semmc.rs 716 LOC and the board's equivalent), RRAMC flash programming, the WDT (obc-boot/src/wdt.rs), and obc-boot's InstallIo binding (install.rs 163 LOC). No phone is needed for anything in this area even now: the phone's bytes are hand-built in the obc-link harness (flat_harness/mod.rs:1-7) and pinned by vectors on both sides.

Seams that already exist and are the right ones: (1) `obc_storage::flat::BlockDevice` (device.rs, 28 lines) with `SparseDisk`/`FaultOnce`/`When` (sim.rs) — deterministic, page-tearing, cut-able media; (2) `obc_link::flat::{Engine, Link, Channel, Reaction, Store}` — transport-free protocol engine that the board binds identically (obc-fw-nrf54l/Cargo.toml:163-165); (3) `obc_dfu::engine::InstallIo`, `armer::{StageIo, ArmIo}` — mocked with op logs in obc-dfu/tests; (4) `obc_formats::io::{ByteSource, ByteSink}` for every reader; (5) host media `obc_host_core::flat_store::HostMedia::{Memory, File}` (flat_store.rs:48-52) — a third in-memory card that could simply be SparseDisk.

Minimal seam to get a host-side SYSTEM test: none new. `flat_harness::Device<D>` (obc-link/tests/flat_harness/mod.rs:109-138) is already a virtual device (engine + real store + torn-able card). Promote it out of a test module into a small host binary or library entry (e.g. in host/obc-usb or a `virtual-device` host crate) that speaks the v4 records over stdin/stdout or a local socket, and the TS usb client (builder/app/src/lib/usb/protocol.ts) and Swift TransferClient can run real upload/download/list/remove flows against it in their own suites. HIL and phone then plug in at the same seam later: a real card behind BlockDevice, a real radio behind Link/Channel. For boot, the honest answer is that InstallIo over sEMMC/RRAMC stays on-glass; do not build a host seam for 163 lines of HAL glue.
