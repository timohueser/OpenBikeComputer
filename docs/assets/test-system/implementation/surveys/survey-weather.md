# weather — weather (host/obc-wx-bake, host/obc-wx-client, firmware/obc-weather, obc-app weather*, obc-sim weather*, ops/weather, tools/rain-radar-demo, companion-ios OBCWeather*/OBCWeatherWire*, CI test-weather matrix, wx-freshness.yml)

## how_it_works
Bakery (host/obc-wx-bake). Production code is driven through three seams and nothing else: (1) `source::Adapter::bake(&mut dyn Upstream, now, &mut warnings) -> BakedSource` per provider; (2) `fetch::FixtureUpstream`, a URL->bytes map with optional ETag (used at tests/canonical_mosaic.rs:128-135, canonical_publication.rs:41), so no test opens a socket; (3) `canonical::run_cycle(lattice, adapters, upstream, store, now, threads, _)` writing into `publish::DirStore` (a directory), read back by `support::published_tree` (tests/support/mod.rs:4-18). Tests shrink the lattice with `sub_lattice` windows of the canonical 0.01 degree grid (canonical_mosaic.rs:68, pack/window.rs) so debug builds can encode them. Captured upstream bytes come from the fixture registry through `obc_fixtures::read(package, name)` (host/obc-fixtures/src/lib.rs:32-60): missing package = skip in plain `cargo test`, hard panic under OBC_REQUIRE_FIXTURES=1, which `obc test` and CI both set (tools/justfile fixture_env; ci.yml:427-433). Captured tests are gated by the Cargo feature `external-fixtures` (Cargo.toml `[features]`), per-test in canonical_mosaic.rs (11 x `#[cfg(feature = ...)]`) and per-file in event_pack*.rs, fuzz_decode.rs, nowcast_skill*.rs (`#![cfg(feature = ...)]`); opera.rs is ungated and reads the two in-repo OPERA crops via CARGO_MANIFEST_DIR (tests/opera.rs:20). Assertions are on: published OBCG cell values vs independently decoded upstream rasters (canonical_mosaic.rs:144-220 decodes the DWD tar and ICON GRIB without bakery code), manifest<->tree consistency and byte-identity between two runs (1239-1323), fail-closed on corrupt bytes (1401-1455), and, for event packs, byte-identity of `pack::rebake::verify_rebake` (src/pack/rebake.rs:110-130) against the stored `service/` tree plus request accounting (event_pack.rs:109-151). Nowcast skill tests decode the truth ladder and compute CSI (nowcast_skill.rs, nowcast_skill_events.rs).

Client (host/obc-wx-client). `WeatherClient` over an `http::Http` trait with `FixtureHttp`/`FaultyHttp` fakes (tests/client.rs:16); shard objects are encoded at test time by the production OBCG encoder over the derived grid (client.rs:70-96), MET hourly from one captured JSON (tests/fixtures/met-freiburg-24h.json). Assertions are on the OBCW bundle the client assembles (quality flags, holes, dry-vs-nodata, corridor geometry, cache behaviour, Range handling). The manifest contract is cross-pinned with Swift, Python and TypeScript through specs/vectors/wx-manifest-v2.json (12 consumer files).

Device (firmware/obc-weather, firmware/obc-app). The no_std reader is driven with synthetic OBCW bundles built by `obc_formats::obcw::encode_format` (obc-weather/tests/freshness_gaps.rs:17-40; obc-app/tests/weather_ride.rs:104-164, weather_hostile.rs:215) and one vector (obc-weather/src/cache.rs:413). obc-app tests drive the production `App` with `weather_snapshot`/`weather_pass` helpers from src/harness/support.rs:409/456 and assert on states, alert decisions and rendered frames (weather_screens.rs). The simulator adds `--weather demo:<scenario>` synthetic bundles (apps/obc-sim/src/weather_store.rs:144-241) and `--weather live` (weather_live.rs), the one real network path, which routes real R2 bytes through obc-wx-client into the same SimWeather.

Ops. ops/weather/freshness_probe.py reads a live or local manifest and exits 0/1/2 (docstring lines 1-38); its 24 unit tests feed it the shared vector (tests/test_freshness_probe.py:34). wx-freshness.yml runs the probe every 15 minutes against the deployed service and manages an alert issue.

CI. The `test` job compiles `--workspace --all-features` and runs nextest with `-E 'not package(obc-wx-bake)'` (ci.yml:284) — the bakery test binaries are still compiled there. `test-weather` (ci.yml:382-441) is a 4-leg matrix, each leg again compiling `--workspace --all-features`, hand-partitioning the bakery: airmass binary alone, canonical_mosaic split 1/2 and 2/2 by nextest partition, and 'the rest'. The registry routes it via a second ownership row that claims the literal run line (suites.toml:439-447). Measured on develop run 34726007195 (warm cache): nextest step 25 s / 45 s / 130 s / 113 s; job wall 46 s to 159 s; the whole weather matrix finishes inside the 4 min 10 s `test` job, so it adds ~7 runner-minutes and 0 wall-clock minutes. Summed native case time 335.7 s over 206 cases: airmass rebake 110.1 s, derecho truth ladder 31.9 s, canonical determinism 26.4 s, corrupt upstream 24.5 s, skill_events 19.6 + 16.2 s, fuzz rv tars 16.6 s, native-instant 11.4 s; the 136 inline unit tests take 2.67 s and the 4 publication tests 0.17 s. Local: `obc test fixtures -p obc-wx-bake` runs plain `cargo test --features external-fixtures` (tools/justfile:598-603), i.e. binaries serially, and needs the 38.7 MB weather packages synced (local cache is 1.3 GB for all registry packages).

## strengths
- Every weather test in every language is hermetic: the Adapter/FixtureUpstream/DirStore seams (bakery) and the Http trait fakes (client) mean no socket is opened anywhere except the manual `--weather live` sim flag (host/obc-wx-client/tests/client.rs:1-4, apps/obc-sim/src/weather_live.rs:1-7).
- Captured data is NOT in git: only two 249 KB OPERA tile crops are tracked; everything else is content-addressed in the fixture registry with sha256, byte ranges, retrieval URLs and licences recorded (host/obc-wx-bake/tests/fixtures/README.md, fixtures/catalog.toml:33-66). This is the right shape for a fixture tier.
- One cross-language contract corpus: specs/vectors/wx-manifest-v2.json plus the OBCG/OBCW vectors are consumed by Rust (bakery, client, device), Swift, Python (probe) and TypeScript (demo), so the phone, the device and the service are pinned to the same bytes without any of them talking to each other.
- The publication split (PR #1662) proved the isolation/retention contracts run in 0.17 s on a synthetic Adapter (tests/canonical_publication.rs) — the pattern to extend.
- The corrupt-upstream test is a real system property (fail closed, previous generation untouched) exercised through the production cycle, not a mock.
- Inline unit tests are cheap (136 tests, 2.67 s) and the bakery's src has no test-only production seams beyond the Upstream/Store traits it needs anyway.
- Event packs record both the canonical URL and the archive URL and store the raw truth upstream, so the pack survives the mirror going away (tests/events/README.md 'three rules').

## no_hil_story
Weather needs no hardware and no phone to be tested end to end; every boundary already has a host-side seam, and the only thing that touches a network is the manual `--weather live` sim flag. The boundary types: on the service side `obc_wx_bake::source::Adapter` (bake over `&mut dyn Upstream`), `obc_wx_bake::fetch::FixtureUpstream` (URL->bytes, ETags), `obc_wx_bake::publish::DirStore` (the store trait, directory-backed) and `obc_wx_bake::pack::Event` + `pack::rebake::verify_rebake` (a frozen upstream+service+truth tree in the registry). On the phone/client side `obc_wx_client::http::Http` with `FixtureHttp`/`FaultyHttp` (host/obc-wx-client/src/http.rs) and `WeatherClient::fetch` producing OBCW bytes; the Swift twin uses `StubWeatherHTTPClient`. On the device side `obc_weather::WeatherReader`/`WeatherCache` over `obc_formats::io::SliceSource`, and `obc_app::App` fed through `weather_snapshot`/`weather_pass` (firmware/obc-app/src/harness/support.rs:409,456), plus the simulator's `SimWeather::from_bytes` (apps/obc-sim/src/weather_store.rs:220) and the headless `--png` renderer used by firmware/ui-snapshots.sh.

What cannot be exercised today without a phone: the BLE upload of the OBCW bundle from the companion to the device and the iOS job engine's real URLSession/background scheduling (URLSessionWeatherHTTPClientTests is 81 LOC; WeatherJobEngineTests use stubs). What cannot be exercised without the live service: nothing that matters for correctness — freshness is a property of the deployment, which is why the probe is an ops monitor.

The one missing seam is trivial and cheap: point `FixtureHttp` at an event pack's `service/` tree (the keys are exactly the R2 keys: `wx/v2/manifest.json`, `wx/v2/<gen>/f<off>/s<col>-<row>.obcg`, tests/events/README.md:12-16) and run `WeatherClient` -> OBCW -> `SimWeather::from_bytes` -> `App` -> frame. No bake is involved (the pack's service tree is pre-baked and byte-verified elsewhere), so the whole product->screen chain costs well under a second and works in obc-sim's own test target, which already depends on obc-wx-client, obc-weather and obc-fixtures (apps/obc-sim/Cargo.toml:13,21,25). Later, HIL can plug in at the same OBCW bytes (upload over the DK VCOM harness) without changing the test.
